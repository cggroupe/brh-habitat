### 🐛 1. Connexion particulier / affilié buggée — login employé impossible ✅ FIXED 2026-05-12

**Symptôme** : « Au niveau des connexions, ça bug un peu toujours au niveau particulier, affilié, tout ça. C'est un peu moyen. » + « Au niveau de mes employés, j'ai pas réussi à me connecter. »

**Cause racine identifiée** :
1. **Employé** — `isBrhEmployee()` dans [src/lib/brh-employees.ts](../../src/lib/brh-employees.ts) lisait UNIQUEMENT le seed statique `BRH_EMPLOYEES` (Pierre Collard demo). La table DB `brh_employees` (Phase Employé V2) n'était JAMAIS consultée. Tout employé prod bloqué sur `/tableau-de-bord` post-login.
2. **Particulier legacy** — `listAccessiblePortals` dans [src/pages/public/LoginPage.tsx](../../src/pages/public/LoginPage.tsx) rejetait `role === 'user'` (valeur par défaut avant migration `20260403100002`). Les comptes anciens ne matchaient aucune card portail.
3. **UX inscription** — Le message « Email de confirmation envoyé » s'affichait en rouge erreur via `setError()` au lieu d'info bleu → utilisateur croit que l'inscription a échoué.

**Fix livré** :
- Cache module-level `Map<email_lower, BrhEmployee>` dans `lib/brh-employees.ts` + `loadBrhEmployeesFromDb()` async hydratée au login + au refresh session. Debounce 30s. RLS Supabase auto-filtre.
- `useAuth` hydrate au `validateSession` + purge cache au `signOut` (évite employé fantôme dans même tab).
- `LoginPage.handleSubmit` appelle `loadBrhEmployeesFromDb()` AVANT `listAccessiblePortals`.
- `LoginPage.listAccessiblePortals` accepte `role === 'user'` au check particulier.
- `RegisterPage` : nouveau state `info` séparé de `error`, style bleu `bg-blue-50 border-blue-200 text-blue-700`.

**Vérif build** : `npx tsc --noEmit` exit 0 + `npx vite build` exit 0 (built in 25.78s).

Voir [log.md](log.md) entrée « 2026-05-12 (soir) — Fix bugs login persona » pour détails complets.

**Priorité** : 🔴 → ✅ Fermé.
**Effort réel** : S (≈ 1 h).

### 🎨 3. Cadastre — marker non cliquable, doit cliquer la parcelle elle-même ✅ FIXED 2026-05-12

**Symptôme** : sur `/agence/foncier/carte`, après recherche d'adresse (ex « 5 rue de Siam »), l'aiguille (marker Leaflet 📍) ne déclenche pas l'ouverture de la fiche cadastrale. Il faut cliquer **directement sur le polygone de la parcelle**. Frustrant car contre-intuitif.

**Constat code** : composant `AgenceFoncierCarte` — handler `onClick` probablement attaché uniquement au layer GeoJSON parcelles, pas au `<Marker>`.

**À faire** :
- Ajouter handler `eventHandlers.click` sur le `<Marker>` qui déclenche le même `openParcellePopup(idu)` que le polygone.
- Idéalement : popup combinée marker + parcelle quand les deux coïncident.

**Priorité** : 🟠 UX gros.
**Effort estimé** : S (~30 min).

**Fix livré 2026-05-12** :
- `AgenceFoncierCarte.tsx` : `handleAddressSelect` ouvre maintenant le popup du marker **dans le `onSuccess`** du `fetchParcelle.mutate` (après que `selectedParcelles[0]` soit set), pas avant. Évite le timing race où le popup s'ouvrait vide « Chargement… » → user le ferme avant la fiche complète → doit re-cliquer sur le polygone.
- Ajout d'un `eventHandlers.click` explicite sur le `<Marker>` qui force `openPopup()` (au cas où l'user re-clique sur l'aiguille après l'avoir fermée).
