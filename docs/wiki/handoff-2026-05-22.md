## ⚠️ Dette technique

### 🔴 Critique
- **76 migrations Phase 11+ pré-existantes** non trackées dans `schema_migrations` (héritage avant refonte 21/05). Audit 4-6h pour `supabase migration repair --status applied` en batch. Voir [bugs-ouverts.md](bugs-ouverts.md) section dette héritée.
- **`brh_employees` rôle `'employe'`** non autorisé par `profiles.role_check` (seuls `admin/pro/particulier/user`). Les RPCs cherchent `role IN (admin, pro, employe)`. Mismatch silencieux : tous les employés utilisent `role='admin'` en pratique.

### 🟡 Limitations connues
- **Score V2 dept 44** = 5 fixe sur DPE E (manque data communale)
- **Score V2 DPE E** plafonne à 55 max (14 règles IRIS toujours NULL)
- **193 DPE E sans `code_insee`** (lat/lng manquant à la source ADEME)
- **`brh_dpe_prospects` filtré F/G/E uniquement** — A-D non ingérés (choix métier)
- **`brh_personnes_historique` sans `adresse_ban_id`** — enrichissement BAN à l'ingestion ferait passer matches 419 → 95%+
- **Bundle Vite > 600 KB** — lazy-loading recommandé

### 🟢 Règles anti-saturation DB (déjà documentées dans `CLAUDE.md`)
1. JAMAIS regex full-scan sur grande table (utiliser colonne générée + index)
2. JAMAIS batches concurrents lourds sur même DB
3. TOUJOURS index sur WHERE/JOIN si table > 50k rows
4. Migration corrective = colonne générée STORED
5. Si saturation : STOP batches + analyser, pas restart en boucle
